# 还在手抄参考图的配色？让 FigEcho 把视觉系统直接“扒”下来

画技术图的人都懂这种痛点：刷到一张排版考究的架构图，想照着画一张自己内容的，结果抄完配色就四不像——容器宽度对不上、箭头语言不统一、字体层级乱成一片。最后要么花一整天硬调，要么干脆放弃“复用风格”这个念头。

更难受的是，市面上所谓的「AI 画图工具」大多只能给你一张长得像 AI 的图，配色撞脸、布局千篇一律。它们不理解：技术图的辨识度来自布局节奏、容器嵌套、箭头组织、字体分级、图标抽象度这一整套视觉语法，单纯抄几个色值根本撑不起风格。

如果你也在为这件事头疼，FigEcho（图易现）可能正好是你要的答案。

![](/assets/blog-images/figecho-1eezs6/img02.webp)

## 一、什么是 FigEcho？

FigEcho 是一个面向技术图的 AI Agent Skill，主要语言 Python，当前版本 0.1.0，GitHub 已获 35 Star。它的核心能力只有一句话：从参考图里提炼可迁移的视觉系统，再把新内容组织成同一视觉家族的新图。

它把视觉风格拆成 5–7 个高辨识度锚点——布局、组件、连接线、配色、字体、图标、密度——每个锚点都带证据、权重和迁移规则，最终编译成一份脱离原图语境也能独立使用的中文分模块提示词。这份提示词既可以单独拿走，也可以搭配新内容规划一键出图。

更实用的是：喜欢的风格可以保存为 Style Pack 进本地风格库，按名字或用途检索复用，下次直接调用，不必每次重新分析。

## 二、核心功能深度解析

### 1. 视觉指纹提炼：不抄配色，抄“语法”

FigEcho 不接受「科技感」「简洁」「高级」这种模糊描述。它会把参考图拆成 5–7 个具体锚点，比如「非对称宽度节奏」「粗黑宏观边界」「浅灰标题带三级容器」「粗黑实线配白心三角箭头」。每个锚点都有证据图位置、权重和迁移规则，新内容只继承这套语法，不继承源图的业务结构。

### 2. 中文分模块提示词：可直接复用

最终交付的不是一句英文摘要，而是一份自包含的中文分模块提示词，包含图像类型、内容结构、整体版式、组件语言、连接线、配色、字体层级、视觉气质、关键风格特征和生成约束。后续无论是换内容还是换模型，都可以拿这一份提示词直接出图。

### 3. 风格库 Style Pack：命名、别名、检索、复用

每个 Style Pack 包含命名、别名、适用场景、完整提示词、视觉指纹、原始参考图和验证记录。模板先以 candidate 状态保存，通过真实成图验证后晋升为 validated，再完成跨主题迁移测试后 portability_status 才变为 passed。仓库自带 6 个示例模板，覆盖黑框衬线架构图、层带灰名列架构图、马卡龙套盒方法图、俏皮卡通手绘示意图、炭黑虚线节点科普图、科研申报总体路线图。

### 4. 双重验证：区分“画得像”和“能迁移”

rendered validation 检查真实成图是否体现了风格锚点；portability validation 要求在不同主题下重新规划拓扑、派生图标题材、重映射色彩语义，并确认没有源内容残留。两者分别记录，不能互相替代——这是防止“只是长得像原图”名不副实的关键设计。

## 三、技术亮点与性能数据

FigEcho 的工程化做得相当扎实。它把「style-prompt.md」设为唯一的风格约束源：成图时的 prompt.md 由它填入内容与图示规划生成，不另写简化英文摘要，保证最终交付的提示词与实际生成调用完全一致，避免「提示词和出图对不上」的常见踩坑。

图像后端兼容性强：Agent 自带可接收参考图的图像工具时优先使用内置工具；没有内置工具时，scripts/generate_figure.py 可依次尝试 Labnana GPT-Image-2、Nano Banana、OpenAI 官方、Gemini 官方或自定义命令。运行 python scripts/generate_figure.py --precheck 即可检查当前可用路线。

风格库支持本地持久化目录，通过 FIGECHO_LIBRARY 环境变量指向独立位置，避免升级或重新安装 Skill 时遗漏个人模板。

## 四、适用场景与人群

场景一：技术博主做系列科普图。想统一专栏视觉风格，每次新选题都能延续既有辨识度，而不是每篇换一个画风。

场景二：科研团队画课题路线图与技术架构图。需要反复产出同风格的高密度信息图，且不同课题的内容结构差异大。

场景三：企业架构师做技术汇报。需要把自家业务架构套进指定视觉规范，既保留风格又避免照抄参考图的业务拓扑。

适合人群：经常产出技术图、对视觉一致性有要求、愿意花一次时间搭模板后续复用的工程师、研究者、内容创作者。

不适合：只想偶尔画一张图、对风格没要求、或者根本不需要复用视觉系统的人——直接用通用 AI 画图工具更省事。

## 五、竞品对比

| 维度 | FigEcho | 通用 AI 画图工具 | 手动抄风格 |
|---|---|---|---|
| 风格提炼 | 拆 5–7 个锚点，带证据权重 | 只能给模糊描述 | 靠眼睛估算 |
| 提示词交付 | 完整中文分模块提示词 | 一句英文摘要 | 无 |
| 内容迁移 | 按新内容重算拓扑 | 易抄源图业务结构 | 手工调整 |
| 风格复用 | Style Pack 本地库，按名字检索 | 每次重新生成 | 依赖源文件 |
| 验证机制 | rendered + portability 双重 | 无 | 纯主观 |

相比通用 AI 画图工具，FigEcho 多了一层「视觉指纹提炼 + 双重验证」，所以不会出现「配色像但布局垮」的情况。相比手动抄风格，它把一次性的体力活固化成可复用的提示词模板。

## 六、如何快速上手

安装到当前项目：

    npx skills add giszzt/FigEcho --skill figecho --copy --yes

从源码运行：

    git clone https://github.com/giszzt/FigEcho.git
    cd FigEcho
    python -m unittest discover -s tests -p "test_*.py"

最小可用流程：准备一张参考图 + 一份新内容描述，运行 Skill 即可获得「分模块提示词 + 同风格新图」。需要直接出图时，按 env.example 配置第三方图片后端的 API Key。

进阶建议：第一次跑通后立刻把风格保存为 Style Pack，后续按 slug 或别名检索复用。

## 七、总结与行动建议

FigEcho 解决的不是「怎么画一张好看的图」，而是「怎么让一系列图长得像一家人」。它把视觉系统从参考图里提炼成可迁移的语法，编译成可复用的提示词，沉淀成本地风格库，再用双重验证保证迁移后不崩。

如果你正被「每次画图都要重新对齐风格」折磨，强烈建议先拿一张你最满意的参考图跑一遍，把生成的 Style Pack 存下来——这可能是你今年性价比最高的一次「风格基建」。
