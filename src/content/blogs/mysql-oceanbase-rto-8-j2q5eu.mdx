## 一、开篇：从踩坑到真香，只差这一个项目

做支付系统的老张最近很烦。凌晨四点，他又一次被报警叫醒——MySQL 主库挂了，备库延迟 30 分钟，恢复时间两小时起步。业务方在群里连发三条问号，CTO 直接拉了对账会议。这不是 MySQL 的错，而是单机数据库的天花板就摆在那里：扩展靠分库分表，迁移苦不堪言，RPO/RTO 永远在赌运气。

而隔壁某互联网大厂早就把核心交易库搬到了 **OceanBase** 上，单集群跑 PB 级数据、TPC-C 跑到 7.07 亿 tmpC，节点扩到 1500 台依然稳如老狗。差距不在团队，不在预算，在选型。

## 二、项目定位：它解决的是什么问题

OceanBase 是蚂蚁集团完全自研的分布式关系型数据库，基于 Paxos 协议构建，对硬件无特殊依赖。它解决的是「既要又要」的传统难题：

- **核心特性**：透明扩展、超高性能、极致成本、HTAP、持续可用、MySQL 兼容
- **项目里程碑**：GitHub Stars 10K+，Apache 2.0 开源，服务 2000+ 客户，覆盖金融、电信、零售、互联网等行业

简单说，这是一个能扛住双 11 流量洪峰、又能跑实时报表的原生分布式数据库。

## 三、核心功能深度解析

### 1. 透明扩展：单集群撑 PB 级数据

OceanBase 单集群支持 **1500 个节点、PB 级数据、万亿行记录**，业务无感知地横向扩容。扩容不需要重新分库分表，应用代码几乎零改动。这种能力来自其原生分布式架构——数据自动均衡、租户资源隔离，集群越大反而越稳。

### 2. 超高性能：双榜登顶

TPC-C 跑到 **7.07 亿 tmpC**，TPC-H 在 30TB 数据量下跑到 **1526 万 QphH**，刷新了世界纪录。这是同等硬件配置下用 C++ 重写每一行代码的结果，从存储引擎到 SQL 执行器全部重新设计，把每一 CPU 周期都榨干。

### 3. 极致成本：存储节省 70%–90%

传统数据库要为高可用付出「双份存储」的代价，而 OceanBase 通过多副本 + 高级压缩，把存储成本砍到原来的 10%–30%。PB 级数据一年省下的钱，够招几个高级工程师。

### 4. HTAP：一份数据，两种负载

同一份数据既能跑高并发事务，又能跑复杂分析查询，**无需 ETL、不增加额外成本**。对于「订单实时统计」「风控实时决策」这类场景，HTAP 是真香特性。

### 5. 持续可用：RPO=0，RTO&lt;8s

基于 Paxos 协议，多数派写入保证零数据丢失；故障切换在 8 秒内完成。机房级灾难都能扛住，是金融级场景的标配。

### 6. MySQL 兼容：迁移无痛

兼容 MySQL 协议和大部分 SQL 语法，现有应用几乎不用改代码就能迁移。DBA 熟悉的 `obclient -h127.0.0.1 -P2881 -uroot` 直接连上就能用。

## 四、技术亮点与性能数据

OceanBase 的技术底座有三大亮点：

1. **Paxos 一致性协议**：多数派写入，副本间强一致，RPO 天然为零。
2. **C++ 自研引擎**：从 LSM-Tree 存储到向量化执行器，全栈可控，性能直接对标专用硬件。
3. **多租户架构**：单集群承载多业务，资源隔离互不影响，运维复杂度断崖式下降。

生态兼容性上，OceanBase 兼容 MySQL 协议、提供 ob-operator 支持 Kubernetes 编排，Docker 镜像覆盖 dockerhub / quay.io / ghcr.io 三大仓库，本地起步零门槛。

## 五、适用场景与人群

**适合谁**：

- 金融、支付、交易类核心系统，对 RPO/RTO 有极致要求
- 互联网大厂需要扛住脉冲流量、又要跑实时分析
- 传统企业正在做「去 IOE」或国产化替换
- 中小公司想直接用云原生数据库，跳过自建分库分表的坑

**不适合谁**：

- 单机小项目、QPS 长期低于 1000 的轻量场景
- 团队完全没有 MySQL 运维经验，又拒绝学习的
- 想要 PostgreSQL 生态的项目（OceanBase 主线兼容 MySQL）

## 七、如何快速上手

**三步跑起来**：

```shell
# 方式一：All-in-one 一键部署（Linux）
bash -c "$(curl -s https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/download-center/opensource/oceanbase-all-in-one/installer.sh)"
source ~/.oceanbase-all-in-one/bin/env.sh
obd demo
```

```shell
# 方式二：Docker 启动
docker run -p 2881:2881 --name oceanbase-ce -e MODE=mini -d oceanbase/oceanbase-ce
docker exec -it oceanbase-ce obclient -h127.0.0.1 -P2881 -uroot
```

**进阶建议**：生产环境建议用 ob-operator 在 Kubernetes 上部署，先用最小集群跑压测，再根据业务特征调整副本数和租户资源。MySQL 迁移过来时，先用全量 + 增量工具做双写验证，再切读流量，最后切写流量。
