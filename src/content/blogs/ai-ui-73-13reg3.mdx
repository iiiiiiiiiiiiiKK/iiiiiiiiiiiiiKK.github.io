## 一、开篇：你还在为这件事头疼吗？

让 AI 帮你写页面，最抓狂的瞬间是什么？

prompt 写得清清楚楚，出来的 UI 却像换了个人——颜色跑偏、字号乱跳、按钮忽圆忽方，跟你想要的产品气质完全不沾边。问题出在 AI「读不懂」你的设计意图，而设计稿又躺在 Figma 里，AI 没法直接吃。

Awesome DESIGN.md 收录了 73 份从真实网站逆向出来的 DESIGN.md，覆盖 Claude、Stripe、Linear、Apple、Tesla、Starbucks 等头部产品，相当于把 73 套「视觉说明书」打包免费送给你。

## 二、项目简介：用一句话概括

Awesome DESIGN.md 是一个 DESIGN.md 资源集合。DESIGN.md 是 Google Stitch 提出的纯文本设计系统文档，AI 编码代理可以直接读取后生成风格统一的 UI。仓库目前收录 73 个站点，仍在持续扩充，MIT 协议开源。

## 三、核心功能深度解析

### 1. DESIGN.md 一键复制即用

每个站点对应一份 DESIGN.md，外加 `preview.html` 和 `preview-dark.html` 两份可视化目录，把配色、字号、按钮、卡片都摆出来供肉眼比对。下载 `DESIGN.md` 丢进项目根目录，对 AI 说一句「按这个风格给我做」，就能拿到与目标站点气质高度一致的页面。

### 2. 九段式结构覆盖设计全维度

每份 DESIGN.md 严格遵循 Stitch 规范，扩展为九个章节：视觉氛围、配色与语义角色、字体层级、组件样式、布局原则、深度与阴影、Do/Don't 守则、响应式断点、Agent Prompt 速查表。比起「随便贴几张截图」的浅层输入，这种结构化描述能让 AI 把 Token、规则、用法一并吃透。

### 3. 横跨七大品类的设计语料库

仓库覆盖 AI 与 LLM 平台、开发者工具、后端与数据库、效率 SaaS、设计工具、金融科技、电商零售、媒体消费、汽车、复古网页十大类，73 个真实站点语料，风格跨度从 Stripe 的紫调极简到 Lamborghini 的黑金肃杀，从 Mastercard 的暖色编辑感到 Dell 1996 的 GIF 贴纸风，单一仓库基本够撑起一个 AI 产品的视觉调研。

### 4. 配套生态把流程串成闭环

遇到没有收录的站点，可以走 getdesign.md 提请求，付费也能拿到私有站点的 DESIGN.md。如果不想从零搭项目，关联的 LaunchKit 提供开箱即用的完整产品模板；想自动化营销分发，还有 EveryFeed 接入 35+ 渠道直接发布。

## 四、技术亮点与性能数据

- 收录规模：DESIGN.md 数量 73 份，覆盖 10 大品类。
- 格式规范：严格遵循 Google Stitch DESIGN.md Specification 的九段式扩展。
- 工程友好：纯 Markdown 文件，无需构建工具、无需 JSON Schema，LLM 直接解析。
- 配套文件：每站附带 `preview.html` 与 `preview-dark.html`，明暗双模式可视化。
- 协议：MIT License，可商用、可二次分发。
- 联动生态：与 VoltAgent 体系打通，向上接 getdesign.md 定制、LaunchKit 模板、EveryFeed 分发。

## 五、适用场景与人群

- 用 Cursor、Claude Code、Lovable 等 AI 编码助手做产品原型，想让 AI 输出「品牌一致」的 UI 时，直接拿对应站点 DESIGN.md 当锚点。
- 设计系统还没建起来的小团队，先借大厂语料快速搭建视觉骨架，后续再替换为自己的品牌资产。
- 做设计调研、竞品视觉拆解、复古网页复刻，Dell 1996、Nintendo 2001 这类条目直接拿来即用。
- 不适合：需要 Figma 源文件或像素级交付的专业设计团队；不打算用 AI 生成 UI 的纯人工开发流程。

## 六、竞品对比

| 资源类型 | 代表方案 | 与 Awesome DESIGN.md 的差异 |
|---------|---------|----------------------------|
| Figma 社区模板 | Figma Community | 源文件精美但 AI 难以直接读取，需要二次转换 |
| Tailwind UI / shadcn | Tailwind UI、shadcn/ui | 提供组件代码但风格相对单一，缺少跨品牌语料 |
| 设计 Token JSON | Style Dictionary 输出物 | 结构化但 LLM 解析成本高，不如 Markdown 自然 |
| AI 设计提示词合集 | 各路 prompt 仓库 | 停留在「一段话描述」层面，缺乏规范化的 Token 与规则 |

Awesome DESIGN.md 的差异化在于「真实站点逆向 + Stitch 规范结构 + Markdown 天然适配 LLM」三点合一，单一仓库就能顶替上面四类资源。

## 七、如何快速上手

1. 克隆仓库：`git clone https://github.com/VoltAgent/awesome-design-md`。
2. 在 `Collection` 中挑一个目标站点，例如想做类似 Linear 的产品，定位到 `Linear` 条目。
3. 把对应 `DESIGN.md` 复制到自己的项目根目录，同时把 `preview.html` 拖进浏览器肉眼确认配色与组件样式。
4. 打开 Cursor 或 Claude Code，prompt 写：「请基于项目根目录的 `DESIGN.md`，为我生成首页 Hero、定价页和注册表单三块组件，输出 React + Tailwind 代码。」
5. 进阶建议：先建一个 `design/` 目录统一收纳 DESIGN.md、preview、字体规范，再让 AI 在生成每个组件前先回读一遍 DESIGN.md，避免上下文漂移。

## 八、总结与行动建议

Awesome DESIGN.md 用 73 份真实站点语料，把 AI 生成 UI 从「猜风格」变成「读规范」。它最大的价值不是好看，而是把大厂多年沉淀的视觉语言压成一份 AI 能秒懂的 Markdown，配合 Stitch 工具链直接落地。

行动建议：先从自己产品对标的 1-2 个站点复制 DESIGN.md 试一次，体验 AI 按规范生成的效果，再决定是否系统化引入到团队工作流。项目地址：https://github.com/VoltAgent/awesome-design-md ，MIT 协议，复制即可商用。
