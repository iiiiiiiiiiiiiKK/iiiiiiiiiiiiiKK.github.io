## 一、开篇：从踩坑到真香，只差这一个项目

上周同事扔过来一本 600 页的英文技术书，PDF 一打开就头皮发麻：通勤两小时，地铁里举着手机看英文，眼睛累到流泪。想听有声版吧，Audible 上搜了一圈，要么没上架，要么单本要 30 多刀。

自己用传统 TTS 工具试过，要么声音像机器人念稿，要么要折腾一整天的 Python 环境，最后输出个几十个零散的 wav 文件，连章节切片都没有。

直到发现了 Audiblez——GitHub 上 8400+ Star 的开源项目。一本 16 万字符的《动物农场》在 Colab T4 GPU 上跑 5 分钟就出成品，CPU 下也只要 1 小时。最关键的是：直接输出 `.m4b` 文件，章节切片、音轨合并、播放器兼容一次性搞定。

## 二、项目简介：它到底是什么？

Audiblez 是一个用 Python 写的电子书转有声书工具，核心定位只有一句话：把 `.epub` 一键变成带章节信息的 `.m4b` 有声书。

它的核心引擎是 Kokoro-82M——一个只有 8200 万参数的 TTS 模型。别看参数小，训练数据不到 100 小时音频，声音却相当自然，已经在 Hugging Face 上开源。

项目当前最新版本 v4，三大升级直接拉满可用性：
- **图形界面（GUI）**：wxPython 写的桌面应用，不碰命令行也能用；
- **CUDA 支持**：通过 `--cuda` 参数启用 GPU 加速，速度提升约 10 倍；
- **多语言覆盖**：支持美式英语、英式英语、西班牙语、法语、印地语、意大利语、日语、巴西葡萄牙语、普通话共 9 种语言，配套 50+ 种音色。

## 三、核心功能深度解析

### 1. 一键生成 `.m4b` 有声书

传统 TTS 流程最痛苦的不是合成，而是后期：要自己按章节切片、用 ffmpeg 拼音频、加章节标记、封装成播放器能识别的容器。Audiblez 把这条流水线全包了，运行 `audiblez book.epub -v af_sky` 后，它会先生成 `book_chapter_1.wav`、`book_chapter_2.wav` 等中间文件，最后合并输出 `book.m4b`，可直接用 VLC、Apple Books 播放，跳转到指定章节毫无障碍。

### 2. 50+ 音色 × 9 种语言

音色命名规则很直观：首字母是国家代码，次字母是性别。例如 `af_sky` 是美式女声 Sky，`zm_yunjian` 是中国男性云健。中文区支持 8 种音色，包括经典的小小、妮妮、小北、云健等，发音自然度远超传统拼接式 TTS。

### 3. 交互式章节挑选（--pick）

不是每次都需要把整本书读完。`--pick` 参数允许在转换前交互式勾选要朗读的章节，跳过前言、目录、参考文献这些不想听的部分，省时省力。

### 4. 语速可调（-s）

支持 0.5~2.0 倍速调节。技术书用 1.5 倍速听爽文、小说用 0.8 倍速品味细节，一条参数切换。

## 四、技术亮点与性能数据

- **Kokoro-82M 模型**：仅 82M 参数，训练数据不足 100 小时，但在自然度评分上超越了许多大参数模型，是当前性价比最高的开源 TTS 之一；
- **GPU 加速**：Colab T4 上转换 16 万字符耗时约 5 分钟，速率约 600 字符/秒；M2 MacBook Pro CPU 模式约 1 小时，速率约 60 字符/秒；
- **架构简洁**：纯 Python 实现，依赖只有 `ffmpeg` 和 `espeak-ng`，跨平台兼容 macOS、Linux、Windows；
- **Apache 2.0 + MIT 双协议**：Kokoro 模型 Apache 2.0，Audiblez 本身 MIT，可商用、可二次分发。

## 五、适用场景与人群

**适合谁**：
- 通勤族：把囤积的英文电子书转成有声书塞进手机；
- 语言学习者：用母语者音色反复听文本，训练听力和发音；
- 内容创作者：把博客文章、教程、自出版电子书批量转音频，拓宽分发渠道；
- 无障碍需求者：为视障人士或有阅读困难的人群提供听书方案。

**不适合谁**：
- 需要专业播音员级别情感演绎的用户（Kokoro 仍然偏中性朗读）；
- Apple Silicon 原生 GPU 加速用户（目前 Kokoro 还没有 MLX 实现，Mac 上只能跑 CPU）。

## 六、竞品对比

| 工具 | 输出格式 | 章节切片 | GPU 加速 | 多语言 | 开源 |
|------|---------|---------|---------|-------|------|
| Audiblez | .m4b | 自动 | 支持 CUDA | 9 种 | 是 |
| edge-tts | .mp3 | 无 | 否 | 100+ | 是 |
| Google Cloud TTS | .mp3/.wav | 无 | 云端 | 50+ | 否（付费） |
| ElevenLabs | .mp3 | 无 | 云端 | 29 种 | 否（付费） |

Audiblez 的差异化在于：**唯一同时支持自动章节切片 + 开源 + 本地 GPU 加速 + 多语言的方案**。edge-tTS 免费但没章节，ElevenLabs 音质顶级但要订阅，Audiblez 正好卡在「够用且免费」的甜蜜点。

## 七、如何快速上手

**环境准备**（以 macOS 为例）：

```bash
brew install ffmpeg espeak-ng
pip install audiblez
```

**最小可用示例**：

```bash
audiblez mybook.epub -v af_sky
```

等待几分钟后，同目录下会生成 `mybook.m4b`，拖进任意播放器即可。

**进阶建议**：
- GPU 加速：`audiblez mybook.epub -v af_sky --cuda`，先确认 PyTorch 已装 CUDA 版本；
- 提速听：`audiblez mybook.epub -v af_sky -s 1.5`；
- Windows 用户建议按 README 在 venv 中安装，避免依赖冲突；
- 想用 GUI 直接跑 `audiblez-ui`，多装 `pip install pillow wxpython` 即可。

## 八、总结与行动建议

Audiblez 把「电子书转有声书」这件事从繁琐的工程问题压缩成了一条命令。8200 万参数的 Kokoro 模型证明了小模型也能做出自然语音，9 种语言 + 50+ 音色 + 自动章节切片 + CUDA 加速，让它在开源 TTS 工具里几乎没有对手。

**使用建议**：技术书首选 `af_sky` 或 `am_adam` 美式男声，1.3~1.5 倍速听；小说可用 `bf_emma` 英式女声，正常语速体验更好。中文内容直接选 `zf_xiaoxiao` 或 `zm_yunyang`，自然度已经接近真人。

**项目地址**：
- GitHub：github.com/santinic/audiblez
- 模型：huggingface.co/hexgrad/Kokoro-82M
- 文档：audiblez --help

一句话安利：装个 Python、敲一行命令，让你的整个电子书库原地变成「私人 Audible」。
