## 一、开篇：为什么你需要这个工具？

每天在不同 AI 客户端之间复制粘贴工作流，把同一套技能、MCP 配置、Google Workspace 凭据反复绑定三遍——这是 AI 重度用户的日常。团队协作时更糟：新成员入职要手把手配置半天，安全审计要看四个客户端的权限面板，模型升级一次要逐个通知到位。市面上的「AI 工作流平台」要么锁死在单一客户端（Claude Cowork 只能用 Claude 系列），要么只支持云端 SaaS（数据出境风险高），要么缺少团队管理能力。一个真正能跨工具、跨团队、可本地化部署的开源方案长期缺位。

## 二、项目简介：一句话说明它是什么

OpenWork 是一款开源跨平台桌面应用，正面替代 Claude Cowork 和 Codex，提供统一的 AI 工作流共享与团队管控能力。项目采用 TypeScript 开发，已收获 21.8K Stars，支持 macOS、Windows、Linux 三端。它通过一个 OpenWork MCP 协议，把技能、插件、远程 MCP 服务、Google Workspace、Microsoft 365 等能力注入任意兼容 Agent，实现「一次创建，处处可用」。

核心关键词：**开源、跨 Agent、团队管控、本地优先**。

## 三、核心功能深度解析

### 1. OpenWork MCP：跨 Agent 的能力中台

OpenWork 的核心是远程 MCP Server（`https://api.openworklabs.com/mcp/agent`），只暴露两个原子化工具：`search_capabilities` 查询可用能力，`execute_capability` 执行能力。安装到 Codex、Claude Code、Cursor、OpenCode 任一客户端后，组织管理员发布的技能、MCP 连接、第三方插件立即可用，无需逐个客户端重复配置。这种「能力即服务」模型，让工作流真正与具体客户端解耦。

### 2. 桌面端独立工作区

OpenWork 提供专用桌面应用作为深度工作场景的承载界面，但不强制使用——已有 Agent 环境的用户可直接通过 MCP 调用。本地优先架构意味着敏感数据不必出境，离线场景也能完整运行；Electron 进程通过 CDP 端口与 Vite dev server 协同，支持多 worktree 并行开发而互不冲突。

### 3. OpenWork Den：团队管控控制面

面向中大型组织，Den 提供五项企业级能力：批量配置推理资源并按成员/团队粒度授权、统一邀请与团队管理、桌面策略下发（含本地模型访问限制和应用版本锁定）、技能与插件市场（Marketplace）支持组织/团队/个人三级分配、导入 Anthropic 兼容插件并桥接其技能与远程 MCP。这一套完整覆盖了从权限、资产到分发的全链路。

### 4. 极简接入路径

OpenWork 提供了三种接入方式：下载桌面应用安装、复制一段 Prompt 让现有 Agent 自动安装配置、命令行直接 `mcp add`。三种路径覆盖了从零基础用户到资深开发者的全谱系，安装门槛被压到接近零。

## 四、技术亮点与性能数据

OpenWork 的技术栈以 TypeScript + Electron + Vite 为骨架，关键设计包括：

- **多 Profile 隔离**：`OPENWORK_DEV_PROFILE=auto` 自动从 worktree 路径派生稳定 profile 名，配合 CDP 端口与 Vite 端口的动态分配（`PORT=0`），支持多分支并行开发无冲突。
- **macOS Keychain Mock**：默认开启 `OPENWORK_ELECTRON_USE_MOCK_KEYCHAIN=1`，避免 Chromium 鉴权 Cookie 持久化时弹出的系统钥匙串模态阻塞 Electron 主循环，开发体验更顺滑。
- **协议兼容性**：完整支持 MCP（Model Context Protocol）标准，兼容 Anthropic 插件规范，理论上任何遵循 MCP 的客户端均可接入。
- **冲突优雅退出**：当第二个实例无法获取 profile 锁时，立即打印原因并退出，避免遗留无窗口进程占用 CDP 端口。

21.8K Stars 反映了社区对其「跨 Agent 中立性」的高度认可，这在当前多数工具绑定单一模型供应商的背景下尤为难得。

## 五、适用场景与人群

**场景一：跨工具 AI 重度用户**——同时使用 Codex、Claude Code、Cursor 的开发者，只需配置一次 OpenWork 工作区，所有客户端共享技能与 MCP。

**场景二：AI 团队协作**——公司内部希望统一管理成员的模型访问权限、发布共享技能市场、审计第三方插件使用情况，OpenWork Den 提供完整后台。

**场景三：数据敏感型企业**——金融、医疗、政企用户需要本地化部署、限制外部模型调用、锁定应用版本，OpenWork 的桌面策略管控能力直接命中。

**适合谁**：跨工具 AI 用户、中小团队 Tech Lead、注重数据合规的企业 IT 管理员。**不适合谁**：仅使用单一 AI 客户端且无协作需求的轻量用户。

## 七、如何快速上手

**方式一：桌面应用**
访问 [openworklabs.com/download](https://openworklabs.com/download)，按系统下载安装包，启动后创建首个工作区。

**方式二：现有 Agent 一键安装**
在 Claude Code、Cursor、Codex、ChatGPT 等任一 Agent 中粘贴以下 Prompt：

`Install OpenWork on my computer, set up my first workspace, and open it ready to use. Follow the steps in https://openworklabs.com/start.md?v=hero`

Agent 会自动完成安装、建工作区、打开界面三步操作。

**方式三：命令行安装 MCP**

Codex 用户执行 `codex mcp add openwork --url https://api.openworklabs.com/mcp/agent`；Claude Code 用户执行 `claude mcp add --transport http openwork https://api.openworklabs.com/mcp/agent`；OpenCode 用户在 `opencode.json` 中添加远程 MCP 配置即可。

**进阶建议**：团队用户优先配置 OpenWork Den，提前规划好技能市场目录与权限层级；本地开发者使用 `pnpm dev:worktree` 并行开发多个分支。

## 八、总结与行动建议

OpenWork 解决了 AI 工作流碎片化的核心痛点：通过 MCP 协议把能力封装为可共享资产，通过 Den 控制面把团队管理标准化，通过开源和本地优先把数据主权交还用户。21.8K Stars 印证了市场对「跨 Agent 中立平台」的迫切需求。

**使用建议**：个人用户从 MCP 接入开始，体验跨客户端复用；团队用户直接部署 Den，建立统一的技能市场与权限体系。
