## 三、项目解析

### Effect-TS/effect — 用类型系统管住 TS 应用的所有“坏味道”

**它把 TypeScript 里最难搞的几个问题（类型化错误、依赖注入、结构化并发、调度、可观测、Schema 校验）打包成了一个统一的运行时框架**，目标只有一个：让你写出来的 TS 应用能扛得住生产环境的复杂场景。

核心能力很硬：传统 `try/catch` 只能捕获同步抛出的异常，Effect 用 `Effect<A, E, R>` 把错误也写进类型签名里，编译器会逼你处理；依赖注入不再是 Angular 那种装饰器写法，而是基于 `Layer` 组合；并发任务可以像 `Promise.all` 一样用，但支持中断、超时和资源清理。

当前 V4 还在 RC 阶段，`main` 分支已经是 v4 开发版；TS 工具链推荐 TS 7，性能和兼容性最佳。

- 适合：写中大型 TS 后端、想告别 `try/catch` 黑洞、追求严格类型契约的团队
- 不适合：刚学 TS 一周的小项目、追求最小依赖的 CLI 工具

**最小上手**

V4 RC 装一下：

```sh
npm install effect@rc
```

写一个带错误类型的函数，让 TS 帮你强制处理失败分支：

```ts
import { Effect } from "effect"

const divide = (a: number, b: number) =>
  b === 0
    ? Effect.fail(new Error("division by zero"))
    : Effect.succeed(a / b)
```

*开源地址：* **https://github.com/Effect-TS/effect**

### iii-hq/iii — 让服务像乐高一样现场拼装

**iii 是一个共享运行时，把队列、定时任务、HTTP、状态、可观测、Agent、沙箱全部收编成一套统一的“现编现用”表面**，核心思路是：用三个原语（Workers、Triggers、Functions）覆盖服务能做的所有事，再也不需要为每个新工具写一堆胶水代码。

亮点在于：每个 worker 一启动就注册到引擎，其他 worker 立刻就能发现并调用它；Agent 缺能力时，可以在运行时动态加一个新 worker，连发现函数、调用、追踪都走同一个接口；SDK 同时覆盖 npm、PyPI、Crates、Docker，TS / Python / Rust 代码都能无痛接入。

- 适合：多语言微服务编排、Agent 平台、需要把第三方能力快速插拔的团队
- 不适合：单个进程的简单脚本、对延迟极度敏感的高频交易链路

**最小上手**

把 iii 跑起来：

```sh
iii compose --namespace dev --up
```

往运行时里加 worker：

```sh
iii trigger -n dev compose::add worker=queue
iii trigger -n dev compose::add worker=agent
```

*开源地址：* **https://github.com/iii-hq/iii**

### jdx/mise — 一个 CLI 顶替 asdf + direnv + make

**mise 把“开发工具版本管理、项目环境变量、任务执行”三件套揉进了一个 Rust 写的 CLI**，配置文件就一个 `mise.toml`，提交进仓库，shell、编辑器、CI 用同一份配置。

支持 Node、Python、Go 等几百种工具的按项目版本切换；`mise use node@24` 一行命令就锁版本；任务声明放在 `[tasks.*]`，自动带上对应工具和 env；还能声明机器引导（系统包、dotfiles、服务）。==注意：首次安装后需把 `mise activate` 加进 shell 配置文件==。

- 适合：多项目多版本共存、想用单一配置打通本地 + CI 的团队
- 不适合：只用一种语言一种版本、坚守 nvm 不想换的人

**最小上手**

一行脚本装好：

```sh
curl https://mise.run | sh
```

试一下指定版本的 Node：

```sh
mise exec node@24 -- node --version
```

*开源地址：* **https://github.com/jdx/mise**

### jetify-com/devbox — 隔离的开发 shell，干净不污染本机

**Devbox 用 Nix 包管理在本地生成隔离的开发环境**，你可以把 Python、Go、Node 当系统级包一样声明在 `devbox.json` 里，启动 `devbox shell` 就拿到一个只属于这个项目的干净 shell。

关键卖点：不走虚拟机，文件系统读写几乎无损；想试新工具就往 shell 里加，用完即弃，本机环境完全不动；同一份 `devbox.json` 能直接转成 devcontainer、Dockerfile 或远程云端开发环境，从本地到生产用同一套工具链。

==注意：底层依赖 Nix，首次启动需要下载包缓存==。

- 适合：多项目版本冲突严重、想给新人“一键环境”的团队、讨厌 Docker 拖累 IO 的开发者
- 不适合：Windows 原生用户（推荐 WSL）、追求零外部依赖的纯前端项目

**最小上手**

一键装上：

```sh
curl -fsSL https://get.jetify.com/devbox | bash
```

初始化环境并加包：

```sh
devbox init
devbox add python@3.10
```

进入隔离 shell：

```sh
devbox shell
```

*开源地址：* **https://github.com/jetify-com/devbox**

### open-gsd/gsd-core — 让 AI 编码助手告别“上下文腐败”

**GSD Core 是一套给 Claude Code、Codex、Cursor 等 AI 编码助手用的“上下文工程 + 规格驱动开发”框架**，它用一套五阶段循环（Discuss / Plan / Execute / Verify / Ship）把 AI 的工作拆给“干净上下文的子代理”，主会话只做轻量协调。

核心思路：每个里程碑都跑一遍同样的循环；研究、规划、执行全部在全新 200k token 子代理里跑；结构化产物（`STATE.md`、`CONTEXT.md`）跨会话保留；Verify 阶段会走查实现并生成修复计划，确认无误才进 Ship。支持 10+ 种 AI 编码运行时（Claude Code、OpenCode、Codex、Cursor、Windsurf 等）。

- 适合：AI 辅助做中大型重构、长任务被上下文撑爆过的开发者
- 不适合：只想让 AI 写个 5 行正则的人

**最小上手**

一条命令装上：

```sh
npx @opengsd/gsd-core@latest
```

新建项目或接管已有仓库：

```sh
/gsd-new-project
/gsd-onboard
```

*开源地址：* **https://github.com/open-gsd/gsd-core**

### tiimgreen/github-cheat-sheet — 59k Stars 的 Git & GitHub 神器清单

**这是一份被收藏了 59k 次的 Git 与 GitHub 隐藏技巧速查表**，从 diff URL 加 `?w=1` 隐藏空白变动，到任务列表、键盘快捷键、提交信息关 Issue、PR Revert、相对链接，几乎把 GitHub 所有“不太显眼但能救命”的特性都列了出来。

亮点：完全开源、章节按 GitHub 和 Git 两大块组织；条目短小精悍，配 GIF 演示；支持英、韩、日、简中、繁中五个语言版本；星标 59k，长期保持活跃维护。新人拿它入门 GitHub，老人拿它当 reference 翻一翻就能找到那种“我以为做不到”的小功能。

- 适合：所有每天都在用 GitHub 的人，尤其是没系统了解过 GitHub 隐藏特性的开发者
- 不适合：完全不用 Git 的人（那基本不存在）

**最小上手**

直接 clone 到本地当手册：

```sh
git clone https://github.com/tiimgreen/github-cheat-sheet.git
```

想看某个 diff 里“只显示真正的代码改动”：

```
https://github.com/owner/repo/pull/123/files?w=1
```

*开源地址：* **https://github.com/tiimgreen/github-cheat-sheet**
